# خطة إضافة اللغتين العربية والإنجليزية

## البنية العامة

- استخدام **مسارات مسبوقة بلغة**: `/` و `/*` (عربي افتراضيًا، RTL) — و `/en` و `/en/*` (إنجليزي، LTR).
- تحويل جميع صفحات الموقع إلى **مسار Layout ديناميكي** واحد يحقن اللغة والاتجاه في `<html dir>` تلقائيًا.
- إنشاء نظام ترجمة بسيط (`t(key)`) بدلًا من مكتبة i18n ثقيلة، لأن المحتوى ثابت وقصير.

## الملفات الجديدة/المعدّلة

### 1) نظام الترجمة (ملفان)
```
src/i18n/dictionary.ts   → قاموس المفاتيح (ar + en) لكل نصوص الواجهة
src/i18n/use-lang.ts     → hook: useLang() → { lang, dir, t, altHref }
```

### 2) الجذر و`__root`
- كشف اللغة من أول segment (`/en/...` → `en`، غير ذلك → `ar`).
- ضبط `<html lang dir>` و`Cairo/IBM Plex` مقابل `Inter/serif إنجليزي`.
- الهيدر: **مبدّل لغة أنيق** `AR | EN` بجوار زر «ابدأ مشروعك» — يبدّل مع الحفاظ على الصفحة الحاليّة.
- الفوتر والنماذج والنيوزلتر: كل النصوص عبر `t()`.

### 3) الصفحات
تحويل النصوص الثابتة إلى مفاتيح ترجمة في:
- `index.tsx` (Hero، Services، About، CTA)
- `projects.index.tsx` (بطاقات التخصّصات)
- `projects.$category.index.tsx`
- `projects.$category.$slug.tsx`
- `contact.tsx` (النموذج، الرسائل، التحقّق)
- `Testimonials.tsx` (العنوان، الشارات — الاقتباسات تبقى بالعربية لأنها آراء أصلية، مع ملاحظة صغيرة بالإنجليزية "Original client reviews in Arabic").

### 4) بيانات المشاريع
- إضافة حقلي `name_en/tagline_en/description_en/approach_en` في `portfolio-data.ts` — سأترجم العناوين والوصف الموجز فقط، مع الإبقاء على أسماء العلامات كما هي.

### 5) الميتاداتا (SEO)
- كل `head()` يقرأ من `useLang()` لضبط `title`/`description`/`og:*` حسب اللغة.
- إضافة `<link rel="alternate" hreflang="ar|en|x-default">`.

## تجربة المستخدم (UI/UX)

- **موضع المبدّل**: أعلى يمين الهيدر (بجانب الـCTA) — قرص صغير `AR / EN` بحدود دقيقة، الحالة النشطة تلبس اللون الذهبي.
- **نسخة الموبايل**: يظهر داخل قائمة الهامبرغر بنفس التصميم.
- **حفظ التفضيل**: خيار اللغة يُخزَّن في `localStorage` — عند فتح الصفحة الرئيسيّة أوّل مرّة يوجّه المستخدم للغته المحفوظة (بدون flash بفضل script صغير في `__root` head).
- **الاتّجاه**: تلقائي (RTL للعربي، LTR للإنجليزي) — كل الـtailwind logical utilities موجودة بالفعل.
- الرابط بين النسختين: نفس المسار مع تبديل البادئة (`/projects/branding` ↔ `/en/projects/branding`).

## تفاصيل تقنية

- المسارات الديناميكيّة الجديدة (TanStack file-based):
  ```
  src/routes/en.tsx                              → layout للإنجليزي
  src/routes/en.index.tsx
  src/routes/en.projects.index.tsx
  src/routes/en.projects.$category.index.tsx
  src/routes/en.projects.$category.$slug.tsx
  src/routes/en.contact.tsx
  ```
  كل ملف إنجليزي هو غلاف رفيع يُعيد استخدام نفس المكوّنات مع تمرير `lang="en"` عبر Context.

- **بديل أبسط** (وهو ما سأتبنّاه لتفادي التكرار): إنشاء `LangProvider` يقرأ من `Route.useMatch().pathname`؛ صفحات `/en/*` تُعاد استخدامها عبر نفس مكوّنات الصفحة الأصلية — أنشئ ملفات `en.*.tsx` تُصدّر مكوّن الصفحة نفسه.

- الترجمات مخزّنة كملف واحد `dictionary.ts` (~250 مفتاح تقريبًا).

## ما يبقى بالعربية فقط

- اقتباسات آراء العملاء (نصوصهم الأصلية) — تظهر بالعربية مع دائمًا `dir="rtl"` داخل الكارت حتى في النسخة الإنجليزية، مع تعليق صغير بالإنجليزية: "Client reviews shown in original Arabic".
- ملف الأعمال PDF (نفس الملف للغتين).

## الأثر

- الحجم: ~10 ملفات مسارات جديدة + ملفّان للترجمة + تعديل ~8 ملفات موجودة لتستخدم `t()`.
- لا تغيير في الـbackend/بيانات المشاريع سوى إضافة حقول ترجمة.
- كل الوظائف الحاليّة (WhatsApp، الفوتر، سلايدر الآراء، النيوزلتر، الفورم) تبقى كما هي وتُترجم فقط.
